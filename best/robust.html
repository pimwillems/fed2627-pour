BEST practice — Robust

Valid, semantic HTML that every browser and screen reader interprets the same way.

Demo 1

Semantic structure and landmarks

This page uses <header>, <main>, <section> and real headings (<h1>, <h2>) in a logical order. Screen reader users can jump between landmarks and headings instead of listening to the page top-to-bottom. Semantics is free functionality — you only have to not throw it away.

Unique IDs

Every id appears exactly once, so each label focuses its own field — click a label to check.





Demo 3

Native checkbox, custom look

A real <input type="checkbox"> styled with CSS: keyboard support, a “checkbox” role, checked/unchecked announcements and a clickable label — all built in. Use native elements first; reach for ARIA widgets only when HTML truly has no equivalent.

The button below is visible to everyone — on screen and in the accessibility tree — and its aria-describedby adds a warning screen readers announce with it. No ARIA fights the native semantics.
